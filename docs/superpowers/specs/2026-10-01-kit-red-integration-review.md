## P2: run lifecycle and controlled launch

Paths: main.rs cmd_run/echo_deltas; engine/runner.rs execute_headless; engine/cancel.rs; engine/registry.rs/supervisor.rs; kit-agents/src/claude.rs/process.rs; existing tests/run_endings.rs/run_json_stdout.rs/run_diff_scope.rs.

Current run --json blocks and emits one final envelope; live progress is unstructured stderr. Receipts are write-once, atomically published after completion; receipt.list cannot be used as a live run feed. RUNNING/CHECKING must come from a currently owned process and structured engine events, not old files or matching task text. Add an opt-in event mode only with live launch: emit typed RunDelta-derived JSONL with runId/sequence/state and final result while preserving current --json behavior. No new daemon. On reload with no retained ownership, show detached/unknown and disable Stop unless ownership is recovered through a supported contract.

Existing execute_headless handles first Ctrl-C cooperatively via CancelHandle, writes KILLED receipt; second Ctrl-C exits immediately without one. Existing agent process-group/job killing is reusable and has no-orphan tests. There is no cancel CLI command. Mod process API must demonstrably send the supported cooperative signal to its OWN Kit child; terminating an outer command or pane is not proof of child cleanup. If not supported, retain terminal handoff or add minimum explicit ownership/control transport. Test stop during agent and gate, host reload/disable, lost process handle, duplicate clicks, permission refusal, and final receipt write failure. No PID-only cross-session kill.

Claude adapter currently uses `claude -p --permission-mode acceptEdits`, protects gate/git/Claude settings in its tool rules, and runs requested checks afterward in engine. It has no observed nested CLAUDECODE handling. Do not silently unset guards or set KIT_FULL_AUTO. Validate actual nested Claude support and inherited permissions in a disposable repo before enabling this agent's launch. Grok currently requires KIT_FULL_AUTO; readiness alone does not mean launchable under mod policy. Present unsupported launch as handoff. Keep explicit agent choice and selected committed base; uncommitted edits are excluded. Long run lifecycle must not use the ten-second read deadline.

Retry can initially be task prefill from receipt.show, visibly reviewed, creating a fresh run; persistent retry linkage needs a small CLI/receipt-sidecar contract if it must survive sessions. Avoid inventing the relationship by task similarity.
